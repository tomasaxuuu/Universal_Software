# Dima — Рекламные воронки и Facebook CAPI

Репозиторий содержит набор лендингов (воронок) и серверный модуль отправки событий в Facebook Conversions API.

---

## Структура проекта

| Папка | Назначение |
|-------|------------|
| `cl--cardiox---l1-vsl/` | Воронка Cardiox — Level 1 (VSL-формат) |
| `cl--cardiox---l2-bf/` | Воронка Cardiox — Level 2 (BF-формат) |
| `fb/` | Серверный модуль Facebook Conversions API (CAPI) |
| `proverca-validnosti-fb-tocena-i-picselya/` | Утилита проверки валидности FB-токена и пикселя |

## 📂 fb/ — Facebook Conversions API

Серверный эндпоинт, который принимает данные о конверсиях через HTTP GET-параметры и отправляет их в Facebook Graph API (server-side tracking).

### Файлы

| Файл | Описание |
|------|----------|
| `index.php` | Основной скрипт обработки и отправки событий |
| `fb_capi_log.txt` | Человекочитаемый лог всех отправленных событий |
| `logs/` | Папка с ежедневными JSON-логами (формат `fb_capi_YYYY-MM-DD.log`) |

### Как работает

1. **Приём данных** — скрипт получает параметры конверсии через GET-запрос:
   - `access_token` — токен доступа Facebook
   - `pixel_id` — ID пикселя
   - `event_name` — тип события (`Lead`, `Purchase`)
   - Данные пользователя: IP, user agent, email, телефон, имя, страна, город и т.д.
   - Данные кампании: campaign, adset, ad, placement

2. **Обработка PII** — все персональные данные (email, телефон, имя, гео) хешируются через **SHA-256** перед отправкой, согласно требованиям Facebook:
   - Приведение к нижнему регистру
   - Удаление пробелов
   - Нормализация телефона (только цифры)

3. **Формирование FBC** — идентификатор клика Facebook строится по трёхуровневой логике:
   - Сначала проверяется GET-параметр `fbc`
   - Затем cookie `_fbc` (с валидацией формата)
   - Если ничего нет — строится из `fbclid` в формате `fb.1.{timestamp}.{fbclid}`

4. **Отправка в Facebook** — POST-запрос на:
   ```
   https://graph.facebook.com/v21.0/{pixel_id}/events?access_token={token}
   ```
   Таймаут: 15 секунд. Ответ логируется.

5. **Логирование** — двойная система:
   - **JSON-лог** (`logs/fb_capi_YYYY-MM-DD.log`) — полный дамп запроса и ответа, версия скрипта, источник FBC
   - **Текстовый лог** (`fb_capi_log.txt`) — краткая строка: время, событие, ID, IP, URL, fbtrace_id

### Поддерживаемые события

| Событие | Особенности |
|---------|-------------|
| `Lead` | Стандартное событие лида |
| `Purchase` | Требует `value` (сумма) и `currency` (по умолчанию USD) |

### Пример GET-запроса

```
fb/index.php?pixel_id=123456&access_token=TOKEN&event_name=Lead&client_ip=1.2.3.4&country=CL&ct=Santiago&sub_id_19=Pedro&sub_id_20=+56912345678&campaign=MyCampaign
```

### Маппинг параметров

| GET-параметр | Назначение | Хешируется |
|-------------|------------|------------|
| `em` | Email | ✅ SHA-256 |
| `sub_id_19` / `fn` | Имя | ✅ SHA-256 |
| `sub_id_21` / `ln` | Фамилия | ✅ SHA-256 |
| `sub_id_20` / `phone` | Телефон | ✅ SHA-256 |
| `country` | Страна (2 буквы) | ✅ SHA-256 |
| `ct` | Город | ✅ SHA-256 |
| `st` | Регион | ✅ SHA-256 |
| `campaign` | Кампания | ❌ raw |
| `adset` | Адсет | ❌ raw |
| `ad` | Объявление | ❌ raw |
| `value` | Сумма (для Purchase) | ❌ raw |
| `currency` | Валюта | ❌ raw |

## 📂 proverca-validnosti-fb-tocena-i-picselya/ — Валидатор FB-токена и пикселя

Веб-утилита для проверки работоспособности Facebook Pixel ID и Access Token перед запуском рекламных кампаний.

### Файлы

| Файл | Описание |
|------|----------|
| `index.php` | Веб-интерфейс (форма ввода Pixel ID и токена) |
| `validate.php` | Бэкенд — выполняет проверки через Meta Graph API |

### Как работает

Пользователь открывает страницу, вводит **Pixel ID** и **Access Token**, нажимает «Check». Скрипт выполняет три проверки:

#### 1. debug_token — Валидация токена
- Запрос к `graph.facebook.com/debug_token`
- Проверяет: валидность токена, привязанные скоупы, ID приложения, название приложения

#### 2. CAPI POST test — Тестовая отправка события
- Формирует тестовое событие с рандомным `event_id`, таймстемпом, IP и user agent
- Отправляет POST на эндпоинт `/events` Conversions API
- Успех: `events_received >= 1` в ответе
- Поддерживает опциональный **test event code** для отладки в Facebook Events Manager

#### 3. pixel_get — Информация о пикселе (опционально)
- Получает метаданные пикселя (ID, название)
- Диагностическая проверка

### Результат

- **✅ OK** — токен валиден И тестовое событие успешно принято
- **❌ FAIL** — токен невалиден или событие не дошло

Ответ содержит HTTP-статусы, raw-ответы от Facebook и структурированный JSON по каждой проверке.

### Дополнительные параметры

| Поле | Описание | По умолчанию |
|------|----------|-------------|
| Graph API Version | Версия API Facebook | `v21.0` |
| Test Event Code | Код тестового события из Events Manager | — |
| Event Source URL | URL источника события | — |

### Назначение

Инструмент для быстрой диагностики перед запуском трекинга — убедиться, что связка Pixel + Token работает и события доходят до Facebook.

## 📂 cl--cardiox---l1-vsl/ — Воронка Cardiox Level 1 (VSL)

Лендинг в формате **Video Sales Letter** — пользователь смотрит видео, после чего появляется форма заказа.

### Файлы

| Файл / Папка | Описание |
|--------------|----------|
| `index.php` | Главная страница с видеоплеером и формой заказа |
| `api.php` | Бэкенд обработки заявок — отправка в партнёрку и FB CAPI |
| `thanks/index.php` | Страница «Спасибо» с подтверждением заказа |
| `thanks/style.css` | Стили страницы благодарности |
| `assets/video2.js` | Логика видеоплеера (popup, fullscreen, таймер) |
| `assets/style_2.css` | Основные стили лендинга |
| `assets/comments.css` | Стили блока комментариев (Facebook-like) |
| `assets/validation.css` | Стили валидации формы |
| `video2/` | HLS-сегменты видео (480p, ~119 файлов .ts) |

### Как работает

#### Шаг 1 — Просмотр видео
- Видео загружается через **HLS.js** (файл `video2/master.m3u8`)
- Стартует в muted-режиме с оверлеем «Нажмите, чтобы продолжить»
- По клику — fullscreen + звук

#### Шаг 2 — Popup заказа
- На **~1400 секунде** видео появляется popup «Закажите сейчас! Осталось 17 упаковок»
- Клик по popup или конец видео → скрывает плеер, показывает форму заказа

#### Шаг 3 — Заполнение формы
- Поля: **имя** и **телефон**
- Скрытые поля: UTM-метки, IP, user agent, fbclid, pixel ID, гео (страна/город/регион), campaign/adset/ad ID

#### Шаг 4 — Обработка (api.php)
1. Извлекает реальный IP (поддержка Cloudflare)
2. Отправляет лид в партнёрскую сеть **offer.store** (`push.json`)
3. Отправляет событие **Lead** в Facebook CAPI (`fb/index.php`)
4. Редирект на `thanks/index.php` с параметрами

#### Шаг 5 — Страница благодарности
- Показывает имя и телефон пользователя
- 3 шага оформления: проверка данных → ожидание звонка → оплата при получении
- Срабатывание Facebook Pixel (Lead event через img-тег)
- Отзывы покупателей

### Защита контента
- Отключены: правый клик, F12, Ctrl+Shift+I/C/J, Ctrl+U, Ctrl+S

### Стек
- PHP, jQuery 2.2.4, HLS.js, Moment.js
- Facebook Pixel + Conversions API
- offer.store API

## 📂 cl--cardiox---l2-bf/ — Воронка Cardiox Level 2 (BF)

Лендинг в классическом формате **статьи/обзора** с таймером, отзывами и формой заказа.

### Файлы

| Файл / Папка | Описание |
|--------------|----------|
| `index.php` | Главная страница лендинга |
| `api.php` | Бэкенд обработки заявок |
| `thanks/index.php` | Страница благодарности |
| `lander/` | Ассеты: стили, шрифты, изображения, слайдер |
| `_preview.png` | Превью лендинга |

### Как работает

#### Лендинг (index.php)
- Продающая страница со статьёй о продукте
- **Таймер обратного отсчёта** (10 минут) для создания срочности
- **Слайдер отзывов** (bxSlider)
- Форма: **имя** + **телефон** (валидация: +56 + 9 цифр для Чили)
- Кнопки прокрутки к форме
- Скрытые поля трекинга: UTM, IP, fbclid, гео, campaign/adset/ad

#### Обработка (api.php)
Логика аналогична L1:
1. Сбор данных + IP (Cloudflare-совместимый)
2. Отправка в **offer.store** (тот же endpoint, offer 1076, flow 12093)
3. Отправка **Lead** в Facebook CAPI
4. Редирект на `thanks/index.php`

#### Страница благодарности
Идентична L1: имя/телефон, 3 шага оформления, отзывы, Facebook Pixel.

### Ассеты (lander/)

| Файл | Описание |
|------|----------|
| `style.css` | Основные стили |
| `media.css` | Адаптивные стили |
| `jquery.bxslider.css` | Стили карусели отзывов |
| `fonts/` | Шрифт Gilroy (regular, semibold, bold) |
| `images/` | Изображения шагов, продукта, иконки |
| `policy.html` | Политика конфиденциальности |

### Отличия от L1

| | L1 (VSL) | L2 (BF) |
|--|----------|---------|
| Формат | Video Sales Letter | Статья/обзор |
| Вовлечение | Видео ~23 мин → popup | Таймер 10 мин + слайдер |
| Ассеты видео | ~119 HLS-сегментов | Нет видео |
| Стиль | Минимализм + видео | Классический лендинг |
| API | Идентичный | Идентичный |
